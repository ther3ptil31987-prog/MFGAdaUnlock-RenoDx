# MFG Unlock 1.4.5 — Engineering & Reliability

This release builds on 1.4.4 with stronger compatibility checks, safer recovery and more reliable diagnostics and latency trials. Local Stable geometry, V2 Compatibility inpaint, native pacing and the existing HUD/UI behavior are retained.

## Changes

- **Stronger kernel identity checks.** Base Blackwell replacements now verify the original cubin's full content and ABI-related metadata, rather than accepting matching resource footprints alone. Unknown content is left to the compatible fallback path.
- **Specific, transactional binary patches.** Architecture gates, Legacy software pacing and frame-count ceiling patches use verified executable and instruction profiles, with preflight and rollback. Single-byte patches retain their write granularity.
- **Safer buffer lifetime and rollback.** Replacement allocations remain alive while descriptors still reference them, including partial restoration failures. Failed or conflicting restores retain their recovery records instead of freeing referenced memory.
- **Improved hook failure handling.** Thread enumeration, registration, installation and detachment failures are reported explicitly. Failed teardown preserves trampoline and hook state.
- **More reliable Latency Guard trials.** Trials wait for successful application before measuring, discard stale or overlapping windows, and distinguish a confirmed native limit from an unknown state.
- **Fewer temporary loader allocations.** Common module notifications use a small local buffer, retaining the long-path fallback and reentrant behavior.
- **Clearer performance diagnostics and provenance.** PresentMon summaries record exact metric definitions and reject incompatible comparisons. Build manifests identify source, flags, payloads and dependency inputs; capture tools can verify the mapped addon against its manifest.

## Compatibility and lifecycle

The locally examined Legacy binary profiles cover Streamline **2.8** and **2.14.16**. Unrecognized binary content is refused instead of patched speculatively; the native pacing path remains the preferred default. This is more conservative than the previous broad pattern search and does not establish support for every runtime sharing a version number.

The addon retains module references and remains resident after the first observed Present. **Completely close and restart the game to change the addon or provider. Hot unload/reload is unsupported**, and in-session OTA unloading may be limited. Transactional writes improve recovery but do not establish a universal safe boundary for concurrent multibyte instruction patching.

## Validation

All **42 automated tests passed**, including provider content mutations, transactional fault injection, buffer-lifetime and hook-failure tests, delayed-application trials, release identity/policy checks. Provider patch/restore roundtrips and numerical GPU harnesses are recorded separately.

The engineering implementation passed **21 provider roundtrips** across 310.9.0, 310.9.1 and 310.9.16, **ten complete blend shader compilations**, **16,384 synthetic photometric cases** and **25,796 border cases in both directions**. These are offline checks, not gameplay benchmarks. The release's final automated-test count and artifact hash accompany the published build.

**In-game validation of this build remains pending. No FPS, displayed-pacing, image-quality or physical-latency improvement has been established.** The release does not remove NVIDIA waits or introduce a new frame pacer. The remaining runtime-dependent investigation items are recorded in the [implementation report](../research/ada-dlssg-engineering-implementation-2026-10-17.md).

## Installation and rollback

Close the game, replace the previous addon with **renodx-mfgunlock.addon64**, keep only one MFG Unlock addon installed, and restart. Existing configuration can be retained; no INI reset is required. This download does not include a new NGX provider, Streamline package or driver.

For rollback, close the process, restore your previous addon or the [1.4.4 release](https://github.com/mavismmg/MFGAdaUnlock-RenoDx/releases/tag/1.4.4), and restart. Do not rely on hot reload to switch builds.

## Building this version

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Build-EngineeringExperimental.ps1 -RenoDxSource <RenoDX-checkout> -Variant release-1.4.5 -OfflineProviders "<semicolon-separated-local-provider-paths>"
```

The internal engineering lifecycle policy is retained, while the dedicated release target, DLL description, panel/log identity and manifest identify **1.4.5**. The historical 1.4.4 experiment and stable control are separate artifacts. Generated NVIDIA-derived payload tables and provider binaries remain local build inputs and are not committed to the repository.
