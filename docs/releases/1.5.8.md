# MFG Unlock 1.5.8 — Exclusive Fullscreen as Borderless

This release lets the XeMFG backend run in games that use exclusive fullscreen, through a new optional setting. It also fixes the version number that Windows reports for the addon.

## XeMFG backend

- **New option: Exclusive fullscreen as borderless.** Intel's frame generation does not support exclusive fullscreen, so XeMFG kept frame generation off when a game used it, and the panel reported *"XeMFG needs a windowed output"*. With this option on, when the game asks for exclusive fullscreen, XeMFG serves it as a borderless window that covers the monitor, and frame generation keeps running. The game is still told that it is in fullscreen, so it does not keep asking to switch display modes. The option is in **General → Smoothness and display**, and is off by default.
  - The monitor's resolution and refresh rate are not changed. If the game renders at a lower resolution, the image is scaled to the screen.
  - It also works for games that start directly in exclusive fullscreen.
  - Alt+Enter is held back while the option is on, so it cannot switch the game to exclusive fullscreen.
  - When the game leaves fullscreen, its window is restored.
  - If the game is already in exclusive fullscreen when you turn the option on, switch the game's display mode once, or restart the game.
- **The panel suggests the option.** When the game is in exclusive fullscreen and frame generation is requested, the panel explains why frame generation is off and suggests switching to Borderless or turning on the new option. The option is never turned on automatically.

## Both backends

- **Correct version number in Windows.** Since 1.5.3, the addon file reported version 1.5.2.0 in its file properties and in the XeMFG log module list, because only the version text was updated. The numeric version now matches the release, and a test checks that the two stay in sync.

## Compatibility

Existing configuration is kept. **Exclusive fullscreen as borderless** stays off until you turn it on; with it off, exclusive fullscreen behaves as in 1.5.7.

## Validation

The automated suite ran **192 tests with no failures**, including new tests for:

- a DLSS-SR game (the Metro Exodus route) entering exclusive fullscreen during frame generation and before its first frame, in SDR and HDR10: frame generation stops in exclusive fullscreen and resumes in windowed mode, with no crash;
- the same transitions with **Exclusive fullscreen as borderless** on, plus a swapchain created in exclusive fullscreen: the game sees fullscreen, the window covers the monitor, frame generation continues, the window is restored on leaving, and Alt+Enter is held back;
- the addon's version resource.

3 artifact-provenance tests skipped because they need the experimental addon and installed PE inputs, which are not part of this build.

Field sessions on NVIDIA driver 621.01 (RTX 4070 SUPER, 240 Hz display):

- **Metro Exodus Enhanced Edition, XeMFG with the DLSS-SR input, RenoDX HDR.** In exclusive fullscreen, frame generation stayed off as before. With the option on, the game's fullscreen request was served as borderless and frame generation ran.
- **Cyberpunk 2077, XeMFG, borderless.** About 16 minutes of play with the option off: frame generation followed the game's toggle as in 1.5.7, with no errors.

A Metro Exodus crash report (addon 1.5.5) led to this release. The crash could not be reproduced: not in the tests above with the same Intel runtime files as the report, and not in Metro Exodus with the RenoDX HDR mod. It points to another component of that system.

These are functional checks; no image-quality or latency measurement was made.

## Installation and rollback

Close the game, replace the previous addon with **renodx-mfgunlock.addon64**, keep only one MFG Unlock addon installed, and restart.

For rollback, close the process, restore your previous addon or the [1.5.7 release](https://github.com/mavismmg/MFGAdaUnlock-RenoDx/releases/tag/1.5.7), and restart.

## Building this version

The addon is the `mfgunlock_native_xemfg` target of `tests/CMakeLists.txt`, published as `renodx-mfgunlock.addon64`; see [Building the XeMFG backend](../../README.md#building-the-xemfg-backend).
