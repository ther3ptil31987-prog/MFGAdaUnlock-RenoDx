# MFG Unlock 1.5.0 — XeMFG Backend

This release adds a second frame-generation backend to the same addon. **XeMFG** runs Intel XeSS frame generation with a multi-frame model at 2x–6x on GeForce **RTX 20, 30, 40 and 50-series** cards, using the inputs a game already produces for DLSS frame generation. The **DLSS-G** backend from 1.4.5 is unchanged and remains the default for new installations.

## Changes

- **New XeMFG backend.** A native ReShade bridge replaces the game's DLSS-G with Intel XeFG and uses XeLL for latency reduction. It is part of the same `renodx-mfgunlock.addon64`, with no OptiScaler or ASI loader. Select it under **General → Frame generation method** and restart the game.
- **Guided Intel runtime installation.** **Diagnostics → Intel runtime files → Install / update files** verifies exact file hashes and downloads the supported `libxess_fg.dll`/`libxell.dll` pair from a pinned commit of Intel's official repository. It updates every Intel copy in the game folder, keeps backups and provides rollback.
- **More input sources.**
  - Games with DLSS frame generation through Streamline.
  - Games that ship their own XeSS frame generation, which now use the panel's 2x–6x multiplier.
  - FidelityFX FSR 3.1 frame generation.
  - An experimental, opt-in DLSS Super Resolution input (`[Adapters] DlssSr=1`).
- **Jittered motion vectors corrected on the GPU.** Games that send motion vectors with camera jitter, such as Death Stranding 2, are converted before frame generation.
- **HDR.** HDR10 output is supported, and scRGB (FP16) HDR output is converted to HDR10 for XeFG.
- **Universal behavior without game-specific code.**
  - Built-in, evidence-backed profiles (`profiles.json`, compiled into the addon) cover the few observed per-game differences.
  - Depth and motion-vector conventions are learned per executable.
  - Newer Streamline structures are read through their known prefix.
  - Late-loaded Streamline interposers are detected, and Streamline 1.x is left untouched.
  - The frame-generation viewport follows the viewport that actually provides inputs.
- **Field fixes.**
  - Resonance: A Plague Tale Legacy: XeLL frame sequencing.
  - Death Stranding 2: repeated depth/motion tags in the same frame, and the game's own XeFG creating its swapchain on another thread.
  - Mafia: The Old Country: an uninitialized probe XeFG context.
  - Assassin's Creed IV: Black Flag Resynced: native swapchain reuse.
- **Diagnostics for bug reports.**
  - A session header and module inventory.
  - XeLL and SDK messages.
  - A compatibility report written beside the game.
  - A field-session replay corpus with a triage tool.

## Compatibility and lifecycle

> **Capcom / RE Engine games (Resident Evil Requiem, Monster Hunter Wilds, Dragon's Dogma 2, Onimusha: Way of the Sword, PRAGMATA):** if you use REFramework, use a build that includes the **XeFG fixes**, such as [onehoon's REFramework](https://github.com/onehoon/REFramework). Builds without them keep reinstalling their XeFG hooks, and GPU utilization drops sharply while XeMFG is active. The panel warns when it detects a REFramework build known to have this problem.

XeMFG requires D3D12, a windowed or borderless display mode and the supported Intel runtime pair. Exclusive fullscreen keeps the game's display mode and leaves frame generation off. Game updates and Steam file verification can restore a game's original Intel DLLs; XeMFG then does not start and the game runs normally until **Install / update files** is run again.

The experimental DLSS-SR input has no camera data from NGX, so it assumes a projection and interpolates the HUD with the scene. It is off by default. In scRGB games, HUD composition from a HUD-less image is not available yet. The FidelityFX input synthesizes latency markers because FSR provides none. Both inputs were validated with fixtures and have not yet been confirmed in a game.

The addon retains module references and remains resident after the first observed Present. **Completely close and restart the game to change the addon, the backend or the Intel files. Hot unload/reload is unsupported.**

## Validation

All **169 automated tests passed**, together with the replay of **nine recorded field sessions**. The automated tests cover:

- numeric GPU tests of the motion-vector dejitter pass (maximum error below 0.001 px) and the scRGB-to-HDR10 encoder (within one 10-bit code);
- smoke and conformance scenarios on the real Intel runtime with Streamline, FidelityFX and NGX fixtures;
- official Streamline sample builds.

XeMFG was tested in Resident Evil Requiem, Monster Hunter Wilds, Dragon's Dogma 2, Onimusha: Way of the Sword, PRAGMATA, Control Resonant, Assassin's Creed IV: Black Flag Resynced, Cyberpunk 2077, The Witcher 3: Wild Hunt (next-gen), Alan Wake 2, The Last of Us Part II Remastered, Mafia: The Old Country, Resonance: A Plague Tale Legacy and Death Stranding 2. Automated launches of the release candidates confirmed active interpolation in eleven of them. These are functional checks; no FPS, displayed-pacing, image-quality or physical-latency improvement over the game's own frame generation has been measured.

> **The Last of Us Part II Remastered frame-pacing capture (October 22, 2026):** one 30-second PresentMon 2.4.1 run with the 1.5.0 release binary, an RTX 4070 SUPER, D3D12, XeMFG at fixed 4x, Hardware: Independent Flip and a manually moved camera. PresentMon labeled **2,164 application frames and 6,495 Intel XeSS-FG frames**, three generated frames per source frame in 2,162 of 2,163 cycles. Output averaged **311.7 FPS** from a **77.9 FPS** source, with a 240.7 FPS 1% low. Display intervals measured **3.20 ms median, 3.59 ms p95, 4.15 ms p99 and 4.82 ms p99.9**, with a 5.31 ms maximum and **no interval above the 6.40 ms large-interval threshold**. Within each source frame, the four display positions averaged 3.19, 3.42, 3.01 and 3.21 ms (standard deviations 0.43, 0.10, 0.24 and 0.12 ms). The source frame time was 12.83 ms ± 0.60 ms (p99 14.56 ms). PresentMon DisplayLatency averaged 23.3 ms (p99 31.1 ms).

This single capture validates the active 4x XeMFG cadence and clean displayed pacing in this game. It is not a comparison with the game's own frame generation or with frame generation off. DisplayLatency is PresentMon's present-to-display measure, not input-to-photon latency.

## Installation and rollback

Close the game, replace the previous addon with **renodx-mfgunlock.addon64**, keep only one MFG Unlock addon installed, and restart. Existing configuration is retained; the DLSS-G backend stays selected unless you choose XeMFG. To use XeMFG, follow the [XeMFG tutorial](../../README.md#installing-xemfg). This download contains the addon only; Intel's runtime files are installed from the panel.

For rollback, close the process, restore your previous addon or the [1.4.5 release](https://github.com/mavismmg/MFGAdaUnlock-RenoDx/releases/tag/1.4.5), and restart. Intel files installed by the panel can be restored with the installer helper's rollback.

## Building this version

The XeMFG-capable addon is the `mfgunlock_native_xemfg` target of `tests/CMakeLists.txt`, published as `renodx-mfgunlock.addon64`; see [Building the XeMFG backend](../../README.md#building-the-xemfg-backend). The DLSS-G backend is compiled with the release 1.4.5 definitions. Generated NVIDIA-derived payload tables, provider binaries and Intel runtime files remain local build inputs and are not committed to the repository.
