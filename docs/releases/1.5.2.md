# MFG Unlock 1.5.2 — DLSS-G Loading Fixes

This is a maintenance release. The DLSS-G backend loads into the game the same way 1.4.5 did, so it is no longer affected by the DLLs that only the XeMFG backend uses. An unreadable backend preference falls back to DLSS-G, and the DLSS-G window hook is installed only while Force Borderless is used. The XeMFG backend is unchanged.

## Changes

- **DLSS-G loads like 1.4.5.** In 1.5.0 and 1.5.1 the addon linked Direct3D 12, DXGI, BCrypt and Shell32 at load time for the XeMFG backend. With `[ADDON] LoadFromDllMain`, these DLLs were mapped inside ReShade's DllMain even when the DLSS-G backend was selected. They now load on first use, and only the XeMFG backend uses them. At load time the addon maps only KERNEL32, USER32 and VERSION, as 1.4.5 did.
- **Backend preference.** `[Backend] Selected` now accepts any letter case and surrounding spaces (`dlssg`, ` XeMFG `). A value that still cannot be read starts the DLSS-G backend, as before 1.5.0, and the panel asks you to select a backend to save a valid one.
- **Force Borderless.** The DLSS-G backend installs its window hook only while **Force Borderless** is on or a window is still being restored. With it off, the game window is not hooked at all, and the control reads **Game controlled**.
- **Diagnostics.** The DLSS-G backend writes one `ReShade.log` line on startup that states how it was loaded: `loaded from ReShade DllMain` or `normal addon loading`. It also notes when an unreadable backend preference was replaced by DLSS-G.

## Compatibility

Existing configuration is kept. No reinstall of the Intel runtime files is needed.

## Validation

All **173 automated tests passed**. A new test reads the published addon's import table and fails if any DLL other than KERNEL32, USER32 and VERSION is linked at load time. It passes on 1.5.2 and fails on the 1.5.1 binary.

Field sessions on NVIDIA driver 621.01 (RTX 4070 SUPER), compared with 1.5.1 in the same games and settings:

- **DLSS-G, Cyberpunk 2077:** loaded from ReShade DllMain, with normal addon loading, and with Force Borderless on. Startup, provider patches, the Streamline hooks and the game's 4x/6x requests matched 1.5.1. There were no crash dumps.
- **DLSS-G, CONTROL Resonant:** loaded from DllMain, and with normal loading plus Force Borderless on. Frames were presented through DLSS-G, matching 1.5.1.
- **XeMFG, Cyberpunk 2077 and CONTROL Resonant:** generated 4x as on 1.5.1.

These are functional checks; no image-quality or physical-latency measurement was made.

## Installation and rollback

Close the game, replace the previous addon with **renodx-mfgunlock.addon64**, keep only one MFG Unlock addon installed, and restart.

For rollback, close the process, restore your previous addon or the [1.5.1 release](https://github.com/mavismmg/MFGAdaUnlock-RenoDx/releases/tag/1.5.1), and restart.

## Building this version

The addon is the `mfgunlock_native_xemfg` target of `tests/CMakeLists.txt`, published as `renodx-mfgunlock.addon64`; see [Building the XeMFG backend](../../README.md#building-the-xemfg-backend).
