# XeMFG — plano de universalização

Fonte: `docs/research/xemfg-universalidade-2026-10-21.md` (auditoria). Branch: `feature/1.5.0-xemfg-universal`. Base: tag `rc5-baseline` (`1c9a0b5`).

**Retomada:** a próxima sessão começa pelo primeiro item com status `pendente` ou `em andamento`. Cada item é um commit. Status possíveis: `pendente`, `em andamento`, `feito (<commit>)`, `bloqueado (<motivo>)`.

## Como verificar cada item

- **Matriz:** `ctest -C Release -LE backlog` em `build/tests` deve ficar 100% verde; os opcionais pulados são os de sempre (`provider_identity`, `engineering_manifest`, `release_1_4_5_manifest`).
- **Backlog:** `ctest -C Release -L backlog` lista os casos ainda vermelhos. Cada item tira o seu caso do backlog (remove o label) e o deixa verde na matriz.
- **Replay:** `ctest -C Release -R xemfg_replay` roda o analisador `tools/xemfg_triage.py` sobre `tests/fixtures/replay/*.jsonl` e compara com `tests/fixtures/replay/expected.json`.
  - Os logs não têm dados para reexecutar o addon; o replay prova que **o diagnóstico continua classificando cada sessão de campo pela causa conhecida**.
  - Quando um item mudar a causa esperada de uma sessão futura, o `expected.json` só muda com nova evidência de campo, nunca para esconder regressão.

- **4.1** `xemfg_dejitter_numeric` (backlog): câmera parada com jitter Halton(2,3) de 8 fases, em três casos de unidade (escala por pixel, escala com sinal negativo, unidades UV). Um bloco com movimento real (3,25; −1,5 px) tem de ser preservado. A convenção vem do Streamline: `jitterOffset` em pixels, MV do atual para o anterior, ponto estático ⇒ `j_prev − j_cur`. Com o repasse atual (identidade), falha com resíduo de 0,333 px.
- **4.2** `native_dejitter.{hlsl,hpp,cpp}`: compute pass (cs_5_0, compilado com `fxc` do Windows SDK num header no build) que subtrai `(j_prev − j_cur)/(mvecScale·tamanho)` do MV, a mesma cancelação do FSR2 `JITTERED_MOTION_VECTORS`. Ele roda numa lista própria (heap de descritores próprio, então os heaps do jogo não são tocados) na fila de apresentação, antes do Present, e o resultado vai ao XeFG como `ONLY_NOW`. A recusa em `CreateOutput` e o caso especial de latência para jitter foram removidos. Sem o jitter do frame anterior, delta = 0 e o histórico é resetado. Logs: `native_dejitter_ready`, `native_swapchain_init` (init_flags, motion_dejitter), `native_dejitter`. O teste numérico agora roda o shader real em WARP, com 4 casos (incluindo subretângulo volátil) e erro máximo < 1e-3 px, e saiu do backlog. O `jittered-motion` interpola com o pass ativo e jitter alternado por frame. **Risco residual:** o sinal da convenção foi validado só por fixture; a confirmação em campo é com DS2 (F.1).
- **4.3** O tag `kBufferTypeBackbuffer` agora é lido: o extent dentro da saída vira `resourceBase/Size` do tag de backbuffer do XeFG no Present (`native_backbuffer_region`). Um extent vazio ou fora da saída mantém o buffer inteiro. O XeFG exige HUD-less com a mesma resolução do backbuffer ("hudless and backbuffer resource resolutions must match"), então a validação de HUD usa a última região declarada. O cenário foi corrigido: o backbuffer é tagueado antes do lote e o HUD-less cobre a mesma região, como num jogo real. O caso saiu do backlog; zero erros do SDK.
